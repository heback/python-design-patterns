파이썬으로 배우는
디자인 패턴

객체지향 원리를 이미 아는 학생을 위한 교재. 장마다 실제 상황에서 출발해, 순진한 설계가 무너지는 지점을 확인하고, 패턴과 파이썬다운 대안을 비교한다.

시작과 정리

서론서론: OOP 원리에서 패턴으로원리를 알면서도 설계가 막히는 순간, 패턴은 무엇을 더해 주는가종합종합: 패턴 비교와 조합닮은 패턴을 의도로 가르고, 변경 축만큼만 패턴을 넣기

생성 패턴

1장팩토리 메서드 (Factory Method)'언제 만들지'는 프레임워크가, '무엇을 만들지'는 하위 클래스가2장추상 팩토리 (Abstract Factory)함께 쓰여야 하는 객체들을, 섞이지 않게 한 번에3장빌더 (Builder)한 번에 만들기 어려운 객체를, 단계적으로 읽히게 조립하기4장싱글턴 (Singleton)'하나여야 한다'와 '어디서든 얻는다'를 떼어 놓기

구조 패턴

5장어댑터 (Adapter)고칠 수 없는 남의 인터페이스를 우리 언어로 번역하기6장데코레이터 (Decorator)같은 인터페이스를 유지한 채 책임을 겹겹이 덧입히기7장컴포지트 (Composite)부분과 전체를 같은 질문으로 다루기8장퍼사드 (Facade)복잡한 서브시스템 앞에 단순한 정문을 하나 두기9장프록시 (Proxy)같은 얼굴을 한 대리인이 실제 객체로 가는 길을 통제하기

행위 패턴

10장전략 (Strategy)교체 가능한 알고리즘을 객체로, 그리고 함수로11장옵저버 (Observer)변화를 알리는 쪽이 듣는 쪽을 모르게 하기12장커맨드 (Command)요청을 객체로 만들어 되돌리고, 묶고, 보내기13장상태 (State)행동이 상태에 따라 달라질 때, 분기 대신 객체를 바꾼다14장템플릿 메서드 (Template Method)절차의 골격은 한 곳에 고정하고, 달라지는 단계만 열어 둔다15장반복자 (Iterator)내부 표현을 감춘 채 순서대로 꺼내기, 그리고 언어가 흡수한 패턴

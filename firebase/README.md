# 탐구학습 진도 서버 (Firebase)

> 현재 화면(학생·교사)은 진도 전달만 쓴다(돌발 퀴즈는 삭제했다). 아래 '제출 → Gemini 초안 → 교사 검수 → 공개' 기능의 서버 쪽(`submissions` 규칙, `generateFeedback` 함수)은 남아 있지만 화면에서는 쓰지 않는다.

## (보류) 피드백 생성기 (Firebase + Gemini)

학생 제출 → Gemini 초안 → 교사 검수 → 공개. 교사 화면은 학교 Google 계정(@ts.hs.kr) 로그인이 필요하고, 제출 가능 여부는 교사 화면 [📮 제출 관리]에서 정한다(기본 닫힘). 접근 통제는 모두 서버(`firestore.rules`, `functions`)가 강제한다.

## 1회 설정 (사용자 작업)
1. Firebase 콘솔에서 프로젝트 생성 → 웹 앱 등록 → 설정값을 `inquiry/firebase-config.example.js`를 복사한 `inquiry/firebase-config.js`에 입력
2. Authentication: **Google** 로그인 사용(학생·교사 모두 학교 Google 계정으로 로그인한다. 익명 로그인은 쓰지 않는다). 설정 > 승인된 도메인에 호스팅 도메인 확인
3. Firestore 생성(`asia-northeast3`), 요금제 **Blaze**로 전환(Functions·Secret Manager 필요)
4. `cp firebase/.firebaserc.example firebase/.firebaserc` 후 프로젝트 ID 기입
5. `python3 inquiry/build.py` (정답이 든 `functions/teacher-content.json`, 로그인 게이트 교사 화면 `public/index.html` 생성)
6. `cd firebase && (cd functions && npm install) && firebase functions:secrets:set GEMINI_API_KEY`
7. `firebase deploy --only firestore:rules,functions,hosting`
8. **(필수) 교사 허용 목록**: Firestore 콘솔에서 컬렉션 `config`, 문서 ID `teachers`, 필드 `emails`(배열)에 교사 이메일(`본인@ts.hs.kr` …)을 넣는다. 학생도 같은 도메인의 학교 계정이므로, 목록이 없거나 비어 있으면 **아무도 교사가 아니다**(규칙·함수 모두 닫힘). 규칙으로는 이 문서를 만들 수 없고(교사만 쓸 수 있으므로) 콘솔에서만 만든다. **배포하기 전에** 먼저 만들어 두지 않으면 교사 화면에 들어갈 수 없다.
9. 학생용 `inquiry/student.html`은 기존처럼 배포(`python3 inquiry/publish.py`)

## 진도 자동 전달
교사 화면(왼쪽 메뉴: 환경설정·진도표·대화기록·토큰 사용량·질문 한도)에서 쓴다. 진도 수집 스위치는 [환경설정], 학생 진도는 [진도표]다. 배포는 `firebase deploy --only firestore:rules,functions,hosting`(먼저 `python3 inquiry/build.py`로 호스팅 파일을 새로 만든다).

- **로그인**: 학생은 학습지·교재 화면 위쪽 안내 줄에서 [로그인]을 눌러 학교 Google 계정(@ts.hs.kr)으로 로그인한다. 학습지와 교재 사본이 같은 주소라 한 번 로그인하면 둘 다 쓰고, 기기를 바꿔도 같은 계정으로 같은 진도 문서를 잇는다. 학번·성명을 따로 입력받지는 않고, 교사 표의 이름은 계정 이름(`displayName`, 없으면 이메일 앞부분)과 이메일이다.
- **개인정보 수집·이용 동의**: 학생은 로그인하면(이미 로그인해 있던 학생도) 동의한 적이 없을 때 **동의 창**을 먼저 거친다(`templates/student-auth.js`의 `Consent`, 스타일 `mon-ui.css`의 `cs-*`). 창은 목적·수집 항목(**필수**: 학번·성명·이메일, 학습 이력 정보 — 담당 교사에게 제공 / **선택**: AI 도우미 질문·답 기록과 Google Gemini(미국) 전달)·보유 기간·거부권과 철회 방법을 보여 주고, 필수 항목에 체크해야 [동의하고 시작하기]가 켜진다. [동의하지 않아요]는 로그아웃한다. 기록은 `consents/{uid}`(`uid`·`student{name,email}`·`version`·`ai`·`agreedAt`)이며 **동의 일시는 서버 시각이어야** 규칙을 통과한다. 동의 전에는 `StudentAuth.get()`이 `null`이라 진도 전송·AI 질문이 시작되지 않고, 서버도 따로 막는다: `firestore.rules`의 학생 진도 쓰기는 `hasConsent()`(현재 버전의 동의 문서가 있어야)를, `askAssistant` 함수는 `consentGate`(현재 버전 + `ai: true`)를 요구한다. 학생은 진도 안내 줄의 **[개인정보 동의]**에서 선택 항목을 바꾸거나 **철회**(동의 문서 삭제 → 새 수집 중단 + 로그아웃)할 수 있다. 철회해도 이미 모인 진도·대화 기록은 남으므로 삭제는 교사가 한다(학생이 서버 기록을 지우지 못하는 규칙은 그대로). 교사 [진도표]에는 학생별 **동의** 열과 동의 현황·건수가 나온다(동의 제도 이전의 진도 기록은 '동의 없음'으로 표시되며 새 진도는 받지 않는다).
  - **문구를 바꿀 때**: `Consent.VERSION`(`student-auth.js`), `consentVersion()`(`firestore.rules`), `CONSENT_VERSION`(`functions/config.js`)을 **같은 값으로 함께** 올린다(`functions`의 테스트가 세 값이 같은지 확인). 올리면 모든 학생이 새 문구를 보고 다시 동의해야 하며, 그 전까지 진도 쓰기·AI 질문이 막힌다. 규칙·함수·화면을 모두 배포해야 한다(`firebase deploy --only firestore:rules,functions,hosting`).
  - 보유 기간 문구("수업이 끝나면 담당 교사가 지체 없이 삭제")와 제공 대상은 학교의 개인정보 처리 방침·보호책임자와 맞는지 확인해 고친다.
- **진도 문서**: `progress/{uid}` — 문서 ID는 로그인한 학생의 uid여야 한다(규칙이 강제). 한 학생에 문서 하나이고 남의 문서를 선점할 수 없다. 교사가 [수집 시작](`config/monitor.on`)을 켜 둔 동안, 로그인한 학생의 화면이 아래를 보낸다. **쓴 글의 내용은 보내지 않고**(`hasOnly` 규칙으로 강제, 학습지 글은 학생 브라우저에만 남는다) 키 입력·화면·탭 전환도 수집하지 않는다. 켜져 있는 동안 학습지와 교재 화면 위쪽에 고지 줄이 항상 보이고, 학생이 끄는 스위치는 없다. 전달 항목은 `monitor.js`·`textbook-monitor.js`의 `updateBar`와 이 목록을 같게 유지한다.
  - **교재 읽기 진도**(`chapters`): 장별로 읽은 절 수·전체 절 수·마지막 절. 절이 화면 가운데 40% 띠에 2초 이상 머물면(화면이 보이고 최근 60초 안에 입력·스크롤이 있을 때) 읽은 것으로 센다.
  - **학습지 진도**(`weeks`): 주차별 완료 문항 수·ID·마지막 문항.
  - **화면을 보고 있는지**(`view`·`viewAt`·`leaves`·`awayMs`): `on`(보이고 포커스 있음)·`hidden`(다른 탭으로 옮기거나 최소화해 이 탭이 가려짐, `visibilitychange`)·`blur`(탭은 보이나 다른 창·프로그램으로 포커스를 잃음, `blur`) 중 지금 상태와 그 상태가 된 시각, 벗어난 횟수(on에서 벗어난 횟수)와 벗어난 시간 합계(ms). **무엇을 보고 있는지(주소·제목·내용)는 브라우저가 알려 주지 않으며 수집하지 않는다.** 규칙은 위 필드 외의 어떤 필드도 허용하지 않는다. 횟수·시간은 학생 브라우저에 계정별로 쌓인다(`FocusTrack`, `student-auth.js`).
  - 공통: `student`(이름·이메일), `where`(지금 있는 곳, 예: `교재 전략`, `학습지 2주차`), 활동 시간, 마지막 활동 시각. 두 화면의 쓰기는 `merge`라서 서로의 필드를 덮어쓰지 않는다.
- **교재 사본에서만 집계된다**: 읽기 진도는 Firebase 호스팅에 올라간 교재 사본(`/textbook/…`, `build.py`가 각 장 페이지에 `textbook-monitor.js`·`fb.js`·`student-auth.js`를 넣고 전체 장 목차 `index.html`도 만든다)에서만 모은다. 학습지와 같은 주소여야 로그인 상태가 공유되기 때문이다. GitHub Pages의 교재(`docs/textbook`)는 그대로이며 집계되지 않는다.
- **수집 중지의 증빙**: 진도 수집 스위치(`config/monitor`)는 교사가 직접 쓰지 못하고, 서버 함수 `setMonitor`가 스위치와 켜고 끈 이력(`monitorEvents`: 서버 시각·변경한 교사 이메일)을 한 번에 쓴다. 규칙상 아무도(교사도) 이력을 새로 쓰거나 고치거나 지울 수 없다. 수집이 꺼져 있으면 서버 규칙이 학생의 진도 쓰기를 거부한다. **학생 화면**(학습지·교재)에는 수집이 중지된 동안 "진도 수집이 중지된 상태예요 … 전달되거나 서버에 기록되지 않아요 (선생님이 ○시에 중지했어요)"가 항상 보인다(AI 도우미 대화 기록은 별개라고 함께 안내). **교사 화면** [환경설정]에는 켜고 끈 이력과 "중지 이후 서버가 받은 진도 갱신: 0건" 확인이 나온다.
- **멈춤 표시**: 마지막 활동 후 2분 미만 활동 중, 5분 미만 잠시 멈춤, 그 이상 멈춤(수업 중에만 의미가 있다). 교사 표의 **화면** 열은 보는 중/다른 탭/다른 창과 벗어난 횟수·시간이다. 마지막으로 보낸 값이라 학생이 오래 조작하지 않으면 실제와 다를 수 있다.
- **한계**: 두 창을 나란히 띄워 이 창을 보면서 다른 창을 쓰거나 다른 기기를 쓰는 것은 알 수 없다. 자료를 찾느라 탭을 옮겨도 이탈로 잡히므로 이탈 횟수를 곧 딴짓으로 해석하지 않는다.
- **쿼터 추정**: 학생 120명, 50분 수업에서 쓰기·읽기 각 6천 건 안팎(하트비트 60초). 무료 일일 한도 안이다.
- **개인정보**: 진도 문서에는 이름·이메일이 들어 있으므로 학교의 개인정보 방침에 맞게 수집 기간을 정하고, 수업 뒤에는 [진도 기록 삭제]로 지운다.
- **삭제한 기능(돌발 퀴즈)**: 문항 풀(`quiz.py`)·팝업·`answerQuiz` 함수·`config/quiz`·`quizResponses` 규칙을 지웠다. 서버에 이미 쌓인 `config/quiz`·`quizResponses` 문서는 남아 있으니 필요하면 콘솔에서 지운다.

## 학생 AI 도우미 (`askAssistant`)
학습지·교재 사본 화면 오른쪽 아래의 AI 아이콘(`templates/assistant.js`, `assistant.css`). 학생은 글 또는 사진으로 묻고 AI는 글로 답한다.
- **켜기/끄기**: 교사 화면 [환경설정]의 학생 AI 도우미에서 켠다(`config/assistant.on`, 기본 꺼짐). 꺼져 있으면 아이콘이 없고 함수도 거부한다. 비용을 통제하는 스위치다.
- **누가**: 학교 Google 계정(@ts.hs.kr)으로 로그인한 사용자만(함수가 도메인·확인된 이메일을 검사).
- **현재 화면 맥락**: 교재는 화면 가운데에 있는 절의 글(줄 번호·실행 결과·버튼 제외), 학습지는 그 주차 제목·단계·가운데에 있는 문항과 학생이 그 문항에 쓴 글·코드. 학생이 드래그해 고른 글은 따로 함께 보낸다. 대화창 위쪽에 "AI가 보는 화면"을 보여 준다. 화면 글은 `<screen>`·`<selected>` 태그로 감싸 지시문으로 따르지 않게 한다.
- **입력 제한**: 질문 1200자, 화면 글 6000자, 고른 글 1500자, 이전 대화 6개, 사진 JPG·PNG·WebP 1.5MB 이하(학생 브라우저가 가로세로 1280px 이하 JPEG로 줄여 보낸다). 검증은 `functions/assistant.js`의 `validate`.
- **사용 한도(학생별·장별)**: 학생(uid) 한 명이 **교재의 장 하나(또는 학습지 주차 하나)에서 물을 수 있는 질문은 기본 40번**이고(하루 기준이 아니라 누적), 1분에 6번은 따로 둔다(`config.js`의 `ASSISTANT_*`). 장 키는 화면이 `context.chapter`로 보낸다(교재는 장 slug, 학습지는 `week1`~`week5`). **서버는 `teacher-content.json`에 있는 장만 인정하고 그 밖의 값·빈 값은 모두 `etc`(기타 화면) 한 칸으로 모은다** — 키를 바꿔 가며 한도를 피할 수 없다(다만 학생이 보이는 화면과 다른 *유효한* 장 키를 보내면 그 장의 칸을 쓸 수 있다). 쓴 횟수는 `chatUsage/{uid}.chapters.{키}`. 모델 호출이 실패하면 그 장의 횟수에서 뺀다. 한도 = **기본(`config/assistant.limit`, 없으면 40; 교사가 [질문 한도]에서 0~1000으로 바꿈) + 교사가 학생별로 가감한 값**(`chatQuota/{uid}`의 `all`(모든 장)과 `chapters.{키}`, 각 −1000~1000, 0 아래로는 내려가지 않음). 가감은 함수 `setAssistantQuota`(교사만)가 쓰고, 규칙상 아무도 직접 쓰지 못한다(학생은 읽지도 못함). 학생 화면은 함수 `getAssistantQuota`로 이 장의 남은 횟수를 본다(장이 바뀔 때만 호출). 한도를 다 쓰면 "이 장(○○)에서 쓸 수 있는 질문 N번을 모두 썼어요"를 보여 준다. 예전의 하루 횟수 필드(`day`·`count`)는 더 이상 쓰이지 않는다(기존 학생의 장별 횟수는 0에서 다시 센다).
- **대화 기록**: 학생과 AI의 모든 대화를 `chatLogs`에 남긴다(문서 하나가 질문 1건: 시각, 학생 이름·이메일, 교재/학습지, 보고 있던 화면 제목, 질문, AI 답, 범위 밖 거절 여부, 오류, 사진 여부와 크기, 모델, 토큰 수, 걸린 시간). **사진 파일은 저장하지 않고** 사진을 보냈는지와 크기만 남긴다. 오류·거절한 질문도 기록한다. 학생 화면의 대화창 안내에 "질문과 AI의 답은 선생님이 볼 수 있도록 기록돼요"가 항상 보인다. 교사만 읽고(규칙) 교사 화면 [대화기록]·[토큰 사용량]에서 [대화기록]에서 **쪽 나누기**(20·50·100건씩, 서버 커서 방식, 총 건수는 서버 집계)로 최신 질문부터 보고, 학생·거절·오류·사진으로 서버 쿼리로 걸러 볼 수 있다(조합마다 복합 색인이 필요해 `firestore.indexes.json`에 정의 — **배포는 `firebase deploy --only firestore:indexes`**, 색인이 만들어질 때까지 몇 분 걸린다). 오류 필터는 `failed` 필드를 쓰므로 이 기능을 넣은 뒤의 기록부터 적용된다. [대화기록 삭제]는 400건씩 묶어 모두 지운다(토큰 집계는 그대로). **학생은 기록을 지우거나 고칠 수 없다**(규칙: `chatLogs`는 교사만 읽고 삭제하며 아무도 직접 쓰지 못한다. 학생 대화창의 [새 대화]는 화면만 비우고 서버 기록은 그대로다).
- **토큰 집계**: Gemini 응답의 `usageMetadata`(입력·출력·생각·합계 토큰, 형식이 틀려 재시도한 것까지 합산)를 학생별 `chatUsage/{uid}`의 `total_*` 필드와 반 전체 `stats/assistant`(날짜별 `byDay` 포함)에 `FieldValue.increment`로 쌓는다. 학생별 `chatUsage/{uid}`에는 날짜별 집계 `byDay`도 함께 쌓는다(2026-11-04부터; 그 전의 학생별 사용량은 누적 `total_*`에만 있다). 교사 화면 [토큰 사용량]은 기간(오늘 · 주간=오늘 포함 최근 7일 · 월간=최근 30일 · 전체 · 직접 지정한 날짜 범위, 한국 날짜 기준)을 골라 반 전체 합계·날짜별·학생별 표를 보여 주고, 학생별 날짜 집계가 없는 이전 사용량은 반 전체 합계와의 차이로 한 줄 따로 나타낸다. 예상 비용은 `inquiry/templates/teacher.js`의 `PRICE`(Gemini 3.5 Flash-Lite, 100만 토큰당 입력 $0.30·출력과 생각 $2.50, 2026-11 공시)로 계산한 추정치다(환율은 가정값). 요금·모델이 바뀌면 `PRICE`와 안내 문구를 고친다.
- **크레딧 소진**: Gemini API 키의 크레딧(요금) 한도가 소진되면(HTTP 402/429) 학생에게는 "AI 도우미의 사용량(크레딧)이 모두 소진되어 지금은 쓸 수 없어요. 선생님께 알려 주세요"를 보여 주고, 교사 화면에는 최근 30분 안의 오류 상자로 알린다. Google AI Studio의 결제 설정에서 충전한다.
- **모델**: 학생 AI 도우미는 **Gemini Flash-Lite**(`config.js`의 `ASSISTANT_MODEL`, 기본 `gemini-flash-lite-latest`)를 쓴다. 가볍고 저렴한 대신 범위 판정·설명 품질이 Flash보다 낮을 수 있으니 모델을 바꾼 뒤에는 `check:scope`를 돌린다. `-latest`는 Google이 가리키는 최신 Flash-Lite로 바뀌므로 고정하려면 환경 변수 `GEMINI_ASSISTANT_MODEL`에 모델 ID(예: `gemini-3.5-flash-lite`)를 지정한다. 대화 기록의 `model` 필드에는 이 값이 남는다. AI 코멘트 초안(`generateFeedback`)은 별도로 `MODEL`(기본 `gemini-flash-latest`)을 쓴다.
- **외부 전달**: 질문·사진·화면의 글이 Google Gemini(`GEMINI_API_KEY` 시크릿)로 간다. 대화창 위에 이 사실과 개인정보를 쓰지 말라는 안내가 항상 보인다. 학교의 개인정보 방침을 확인해야 한다.
- **답할 수 있는 범위**: **파이썬, 객체지향프로그래밍, 디자인 패턴**뿐이다(이 교재·학습지의 내용과 푸는 방법 포함). 범위를 프롬프트에만 맡기지 않고 서버가 한 번 더 강제한다 — 모델은 `{onTopic, reply}` JSON만 내고(`assistant-model.js`), `onTopic`이 `true`가 아니거나 형식이 틀리면 모델이 쓴 `reply`를 버리고 정해진 안내문(`REFUSAL`)만 학생에게 보낸다(`assistant.js`의 `finalize`, 단위 테스트로 확인). 질문 속의 "이전 지시를 무시해" 같은 말은 따르지 않게 했고, 사진이 범위 밖이어도 거절한다. 거절한 질문은 대화 기록에 남기지 않는다.
- **범위 점검(실제 모델)**: 모델이 범위를 제대로 판정하는지는 실제 Gemini로만 확인할 수 있다. `GEMINI_API_KEY=키 npm --prefix firebase/functions run check:scope`가 범위 안 8문항(답해야 함)과 범위 밖 14문항(급식·수학·영어·게임·상담·다른 프레임워크·프롬프트 주입 등, 거절해야 함)을 `askAssistant`와 같은 경로로 돌려 통과/실패를 보여 주고, 하나라도 틀리면 종료 코드 1을 낸다. 프롬프트나 모델을 바꾼 뒤에는 다시 돌린다. 키는 저장소에 두지 않는다.
- **교육 정책**: 시스템 프롬프트(`assistant.js`의 `SYSTEM`)가 학습지 문항은 정답을 대신 쓰지 않고 힌트로 안내하게 한다. 일반 텍스트(마크다운 없음), 10문장 안팎, 수업과 무관한 요청은 거절. 정책을 바꾸려면 이 프롬프트를 고친다.
- **시험**: 에뮬레이터에는 키가 없어서 함수가 시험용 답("(에뮬레이터 시험 답변) …")을 돌려준다(`FUNCTIONS_EMULATOR`이고 키가 없을 때만). 실제 Gemini 답변의 품질은 배포 뒤 직접 확인해야 한다.

## 모델·도메인
- 모델: 환경 변수 `GEMINI_MODEL`(기본 `gemini-flash-latest`). 운영 시 고정 ID를 권장.
- 교사 도메인은 `firestore.rules`의 `isTeacher()`, `functions/config.js`, `firebase-config.js`의 `TEACHER_DOMAIN`을 함께 바꾼다.

## 개인정보
Gemini에는 학생의 응답 텍스트와 교사용 기준만 보내고 학번·성명은 보내지 않는다. 학생의 학번·성명·이메일·학습 이력은 위 [개인정보 수집·이용 동의]를 받은 뒤에만 서버에 쌓는다. 다만 응답 본문에 개인정보를 쓰지 않도록 학생에게 안내한다.

## 테스트
```bash
cd firebase/functions && npm test                        # 프롬프트·검증·학교 계정 판정 단위 테스트
cd firebase/test && npm install && cd .. && \
  firebase emulators:exec --only firestore --project demo-inquiry "npm --prefix test test"   # 규칙 테스트
```
로컬 시험: `firebase emulators:start --project demo-inquiry` 후 `http://localhost:5005/?emulator`(웹 config의 projectId를 `demo-inquiry`로).

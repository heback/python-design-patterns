# 요약 판(쉬운 판) 집필 지침

학생들이 교재 분량에 지쳐 한다. 각 장을 **짧고 쉬운 요약 판**으로 다시 쓴다. 기존 긴 원고는 `chapters/full/{nn}-{slug}.html`로 옮겨 두었고 **참고용 긴 버전**으로 남는다(빌드가 요약 판 첫머리에 링크를 자동으로 넣는다 — 원고에 직접 쓰지 않는다). 긴 원고는 수정하지 않는다.

## 산출물 (장마다)
1. `chapters/{nn}-{slug}.html` — 요약 판 원고(본문 조각, 맨 위 `<!--meta-->`). **meta의 title·subtitle·part는 긴 버전과 똑같이** 쓴다(목차·진도표가 이를 쓴다).
2. `src/{nn}_{slug}/easy/*.py` — 요약 판 전용 **짧은** 예제(아래). 긴 버전의 `src/{nn}_{slug}/*.py`는 건드리지 않는다.
3. 연습문제는 쓰지 않는다. 원고 맨 끝에 빈 자리 `<section id="exercises"></section>`만 두고 `python3 .claude/skills/pattern-chapter-writing/scripts/sync_exercises.py {nn}`을 돌리면 긴 버전의 연습문제 절이 **글자 그대로** 복사된다(문제·해설·시작 코드·`data-src` 해설 코드 모두 동일해야 하므로 절대 손으로 고치지 않는다).

## 반드시 지킬 것
- 먼저 `.claude/skills/pattern-chapter-writing/SKILL.md`(장 구조·주석·용어·톤 규칙)와 `chapters/full/{nn}-{slug}.html`(원본)을 읽는다.
- **섹션 id와 순서는 긴 버전과 같게 유지한다**(진도 기록이 절 id로 집계된다). 패턴 장(01~15): `goals, context, naive, structure, implementation, pythonic, tradeoffs, exercises` 8개 — 하나도 빼거나 바꾸지 않는다. 서론(00)·종합(99)은 긴 버전의 절 id 중 핵심만 골라 쓰되 같은 id를 그대로 쓰고(새 id 금지), `goals`와 `exercises`는 반드시 둔다. 절 제목의 번호 접두사("3. …")는 긴 버전과 같은 규칙으로 맞춘다.
- **연습문제가 요구하는 것은 요약 판 본문이 가르쳐야 한다.** 연습문제(긴 버전의 `#exercises`)를 먼저 읽고, 문제·해설·시작 코드가 쓰는 클래스·함수·용어·개념의 이름이 요약 판 본문에 **같은 이름으로** 등장하게 한다(예: 문제가 `FeeInput`을 말하면 요약 판 코드에도 `FeeInput`이 있다). 학생은 요약 판만 읽고 연습문제를 풀 수 있어야 한다.
- 맥락 선행 규칙: `#context`에 코드 없음, 본문의 모든 코드 블록 바로 앞에 `<p class="lead-in">`, `#structure`에 SVG 다이어그램(색 하드코딩 금지, 클래스만). 코드 뒤에는 짧은 해설.
- 코드: 모든 `<pre data-src>`에는 `data-title`(역할 이름: 순진한 코드 / 패턴 코드 / 파이썬다운 변형 …)이 필수. 파일 이름·`src/`·"저장소" 같은 말을 원고·주석·SVG에 쓰지 않는다. 코드 합자 이야기는 하지 않는다.
- 용어: 새 용어를 만들지 않는다(`chapters/terms.json` 수정 금지). 요약 판 본문·코드·연습문제에 `terms.json`의 용어(별칭 포함, `check_terms.py`가 찾는다)가 나오면 **첫 등장 자리에서 `<dfn data-term="id">`로 정의**한다(정의 문장은 긴 버전의 것을 짧게 줄여 써도 된다). 어려운 전문 용어는 가능하면 쉬운 말로 풀어 쓰고 요약 판에서는 아예 안 쓰는 쪽을 택해도 된다. 같은 용어의 `<dfn>`은 요약 판 안에서 한 번만. 연습문제 절 안에 이미 `<dfn>`이 있는 용어(복사본)는 연습문제보다 앞에서 정의하지 않는다(정의가 두 번이 된다) — 그 용어가 연습문제보다 앞에서 쓰이면 앞쪽 설명을 그 용어를 쓰지 않는 말로 바꾼다.

## 분량·쉬운 글쓰기 (핵심)
- 본문 글(코드·SVG·연습문제 제외)은 패턴 장 기준 **한글 약 2,500~3,500자**. 긴 버전의 1/4~1/3이다. 학생이 한 장을 15분 안에 읽고 나서 연습문제로 넘어가게 한다.
- 문장은 짧게(한 문장 한 가지). 추상 설명보다 **구체적인 장면과 한 줄 비유**. 전문어는 처음 나올 때 쉬운 말로 풀고, 같은 것을 부를 때는 같은 단어만 쓴다. 교재체(~다), 독자를 "여러분"으로 부르지 않는다. 학생은 OOP 기본기는 안다(기준선은 SKILL.md).
- 각 절의 구성: `context`(긴 버전 이야기를 **한두 단락**으로 압축, 인물·요구 변경·아픈 지점), `naive`(문제 2~3가지를 목록으로), `structure`(그림 1개 + 참여자 역할 표 또는 짧은 목록), `implementation`(핵심 코드 + "어디를 보면 되는가" 3~4줄), `pythonic`(파이썬에서 달라지는 점 한두 가지만, 짧은 코드), `tradeoffs`(장점 2~3 / **쓰지 말아야 할 때 2~3** / 헷갈리는 패턴과의 한 줄 차이).
- `goals` 아래 또는 `tradeoffs` 끝에 `<div class="callout"><strong>핵심 한 줄</strong> …</div>`로 이 장의 판단 기준을 한 문장으로 요약한다(`goals`는 예고라 용어 첫 등장으로 치지 않는다).
- 구조 다이어그램은 긴 버전의 `#structure` SVG를 **더 단순하게**(클래스 3~5개) 줄여 쓰고, 클래스 이름은 요약 판 코드와 일치시킨다. 긴 버전에 있는 `code-map`(코드 지도) 다이어그램은 쓰지 않는다. `figcaption`의 그림 번호는 `그림 {장}-1` 식으로 새로 매긴다.
- 표는 꼭 필요한 것만. 긴 버전의 사례 여러 개·변형 여러 개는 **하나만** 고르고 나머지는 빼는데, "더 알고 싶으면 참고용 긴 버전"이라는 말은 쓰지 않는다(링크는 빌드가 넣는다).

## 요약 판 전용 코드 (`src/{nn}_{slug}/easy/`)
- 파일: `e1_naive.py`(순진한 코드), `e2_pattern.py`(패턴 코드), `e3_pythonic.py`(파이썬다운 변형). 필요하면 줄이거나 합쳐도 되지만 이름은 `e{번호}_….py`.
- **각 파일 30~60줄 안팎, 코드 전체를 한 블록으로 싣는다**(`data-lines`로 쪼개지 않는다). 긴 버전과 **같은 시나리오·같은 이름**(연습문제가 쓰는 이름)을 쓰되 군더더기를 걷어 낸 최소 예제로 다시 쓴다. 긴 버전의 코드를 줄여서 가져와도 된다.
- 규칙은 그대로: 모듈 docstring(상황 요약 첫 단락), 모든 클래스·함수 docstring, 주석+docstring 비율 ≥30%(의미 있는 "왜" 주석으로), 표준 라이브러리만, 파일 간 import 없음, `if __name__ == "__main__":` 데모가 단계마다 `print("[1] …")`로 출력, 순진한 코드의 문제 지점에 `# ⚠ 문제:`. 역할 태그(`[Strategy]` 등)와 OCP 같은 원칙 연결은 짧게.
- 합자 때문에 `->`를 `→`로 바꾸지 않는다(ASCII 그대로).

## 완료 전 점검 (모두 통과해야 반환)
```bash
python3 .claude/skills/pattern-chapter-writing/scripts/sync_exercises.py {nn}
python3 .claude/skills/code-verification/scripts/verify_chapter.py {nn}     # PASS (WARN '원고에서 참조되지 않음'은 긴 버전 코드이므로 무시 가능)
grep -rnE "[0-9]{2}_[a-z_0-9]+\.py|src/|저장소" chapters/{nn}-*.html src/{nn}_*/easy   # 학생에게 보이는 곳에 없어야 함
```
`check_terms.py`는 책 전체를 보므로 다른 장이 아직 없어 위반이 많이 나온다. **`python3 .claude/skills/code-verification/scripts/check_terms.py --chapter {nn}`** 으로 이 장과 관련된 위반만 보고, 이 장 때문에 생긴 위반(정의보다 먼저 등장, `<dfn>` 개수)은 고친다. `<dfn>`이 0개로 나오는 용어는 긴 버전에만 있는 용어이므로 무시한다(오케스트레이터가 정리한다).

## 반환 메시지(짧게)
만든 파일 목록, 본문 글자 수(코드·SVG·연습문제 제외 대략), `verify_chapter.py` 결과, 연습문제와의 연결에서 신경 쓴 점이나 어려웠던 점 한두 줄.
